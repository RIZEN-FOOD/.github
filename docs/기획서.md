# 라이즌푸드 공식 웹사이트 기획서

**크림오브라이스 단일 제품 브랜드 사이트 + 관리자 시스템**

| 항목 | 내용 |
|---|---|
| 클라이언트 | 라이즌푸드 (RIZEN FOOD) |
| 제품 | 크림오브라이스 — 피트니스용 클린 탄수화물 |
| 1차 범위 | 메인 · 상품 · 공지사항 · 인증 · 관리자 |
| 스택 | Next.js 15 + TypeScript / Spring Boot 3 + Java 17 / PostgreSQL |
| 문서 상태 | v1 — 브랜드 자산·판매 방식 확정 후 갱신 |

> 이 문서는 Claude Code가 작업 전에 읽는 기준 문서다.
> 화면 설계 상세와 와이어프레임은 별도 PDF(기획서_라이즌푸드_웹사이트.pdf) 참조.

## 1. 제품과 시장 이해

### 1.1 크림오브라이스란
곱게 도정한 쌀을 물이나 우유에 풀어 죽처럼 먹는 **탄수화물 보충 식품**. 해외 피트니스 씬의 오래된 스테이플이며 국내에서는 최근 확산 중이다.

| 구매 동기 | 내용 |
|---|---|
| 빠른 소화 | 위 부담이 적어 운동 직전·직후에 적합 |
| 깨끗한 성분 | 지방·나트륨·첨가물이 거의 없음. 대회 준비 식단에 적합 |
| 정확한 계량 | 그램 단위로 식단 관리 가능 |
| 자극 없음 | 장이 예민한 사람, 새벽 공복에도 부담이 적음 |

### 1.2 이 사이트가 넘어야 할 두 개의 벽

**벽 1 — "이게 뭔지 모른다"**
크림오브라이스는 아직 대중적이지 않다. 첫 임무는 판매가 아니라 **"이게 뭐고 왜 먹는지"를 3초 안에 전달하는 것**이다.

**벽 2 — "쌀가루랑 뭐가 다른가"**
도정도·용해도·완성 질감의 차이를 **시각으로** 보여줘야 한다. 말로 설명하면 안 읽힌다.

### 1.3 타깃
1. **운동인** — 벌크업·컷팅 식단 관리자, 대회 준비자
2. **소화 민감층** — 위장이 약한 사람, 새벽 운동자
3. **다이어터** — 정량 관리가 필요한 사람

### 1.4 성공 지표
| 순위 | 목표 | 지표 |
|---|---|---|
| 1 | 구매 전환 | 구매 버튼 클릭 → 판매 채널 이동률 |
| 2 | 제품 이해 | 히어로 스크롤 완주율 |
| 3 | 운영 자립 | 대표가 개발자 없이 상품·배너·공지 관리 |

## 2. 사이트 구조

### 2.1 1차 범위
```
/                     메인 — 히어로 중심 + 상품 섹션 포함
/products             상품 목록
/products/[slug]      상품 상세
/notice               공지사항 목록
/notice/[id]          공지사항 상세
/auth/login           로그인
/auth/signup          회원가입
/auth/find            아이디·비밀번호 찾기
/mypage               마이페이지 (인증 필요)

/admin                관리자
  /admin                대시보드
  /admin/products       상품 관리
  /admin/banners        배너 관리
  /admin/notice         공지사항 관리
  /admin/members        회원 관리
  /admin/inquiries      문의함
  /admin/settings       사이트 설정
```

### 2.2 추후 확장 (구조만 열어둠)
| 확장 항목 | 지금 해둘 것 |
|---|---|
| 레시피 / 먹는 법 | 라우트 예약, CMS 콘텐츠 타입 확장 가능하게 |
| 브랜드 스토리 | 정적 페이지로 언제든 추가 |
| 후기 게시판 | review 테이블을 미리 설계 |
| 장바구니·주문·결제 | **§9 확정 필요** — 범위가 크게 달라짐 |

### 2.3 ⚠️ AUTH 도입에 따른 전제
회원 기능이 생긴다는 것은 자사몰 방향일 가능성을 뜻한다. 로그인의 목적이 ①주문·결제인지 ②후기 작성·문의 이력인지 ③등급·적립인지에 따라 설계 범위가 크게 달라진다.

**본 문서는 ②를 기본으로 하되 ①로 확장 가능한 구조로 설계했다.**

## 3. 메인 페이지 구성

단일 제품 브랜드이므로 히어로가 화면의 대부분을 차지한다. 이후 섹션은 "이게 뭔가" → "왜 먹나" → "무엇이 다른가" → "무엇을 파나" 순으로 설득한다.

| 섹션 | 내용 |
|---|---|
| S0 헤더 | 로고 · 메뉴 · 로그인 · 구매 버튼(항상 노출). 스크롤 시 배경 생김 |
| **S1 히어로** | 제품 무브먼트 애니메이션. 100svh |
| S2 이게 뭔가요 | 3카드 (쌀 100% / 물만 부으면 / 90초) |
| S3 왜 크림오브라이스인가 | 지그재그 3단 (빠른 소화 / 깨끗한 성분 / 정확한 계량) |
| **S4 질감 비교** | 좌우 드래그 슬라이더 — 일반 쌀가루 vs RIZEN |
| S5 영양성분 | 4개 지표, 스크롤 진입 시 카운트업 |
| **S6 상품** | 카드 그리드. CMS의 `isFeatured` 상품만 노출 |
| S7 먹는 법 | 3스텝 |
| S8 후기 | 가로 슬라이드 |
| S9 공지사항 | 최신 3건 |
| S10 구매 CTA | 제품 + 가격 + 구매 버튼 |
| 푸터 | 사업자정보 · 약관 · 개인정보처리방침 |
| 모바일 | 하단 고정 구매 바 |

### 3.1 히어로 애니메이션 명세
| 스크롤 | 연출 |
|---|---|
| 0~15% | 제품 패키지 등장 (fade + scale 0.92 → 1) |
| 15~40% | 파우더 낙하 시퀀스 |
| 40~65% | 물·우유가 부어지며 크림 질감으로 변화 |
| 65~85% | 스푼이 저어지는 루프 |
| 85~100% | 카피 등장, 완성된 그릇 클로즈업 |

**구현 방식 3안**

| 안 | 방식 | 필요 자산 | 판단 |
|---|---|---|---|
| A | 실사 촬영 시퀀스 스크러빙 | 조리 과정 연속 촬영 40~60컷 | 임팩트 최상. 촬영 가능하면 이것 |
| **B** | 정지컷 + GSAP 전환 | 고화질 제품컷 5~8장 (누끼) | **기본안** |
| C | 3D 렌더 | 3D 모델링 | 비용·기간 과다. 권장 안 함 |

**제약**
- 질감이 판매 포인트다. 크림오브라이스는 부드러움이 제품의 정체성이므로 변화 과정을 보여준다
- 모바일은 스크러빙 대신 자동 재생 루프 영상(무음 3~4초) 또는 3컷 페이드
- `prefers-reduced-motion` 존중
- 첫 화면 로딩 2.5초 이내. 시퀀스는 첫 프레임만 즉시, 나머지 지연 로드
- JS 없이도 텍스트가 DOM에 존재해야 함 (SEO·접근성)

> 프로토타입 `rizen-main.html` 이 이미 존재한다. 팔레트·구조·인터랙션의 기준으로 삼는다.

## 4. 상품 페이지

### 4.1 목록 `/products`
- 페이지 헤드 + 정렬(신상품·낮은가격·높은가격)
- 필터는 상품이 늘어나면 활성화 (지금은 숨김)
- 카드 그리드 3열 (모바일 2열), 페이지네이션

### 4.2 상세 `/products/[slug]`
- 상단: 갤러리(줌) + 구매 패널(이름·가격·옵션·수량·구매/장바구니)
- 스티키 탭: 상세정보 / 영양성분 / 원재료 / 배송·교환·환불 / 후기
- 후기: 별점·목록, 작성은 로그인 필요
- 관련 상품
- 모바일 하단 고정 구매 바

> **중요** — 영양성분·원재료·유통기한 등 법정 표시사항은 상세 이미지가 아니라 **텍스트로** 넣는다. 이미지 안의 글자는 검색에도 안 잡히고 접근성에도 불리하다.

## 5. 공지사항

### 5.1 목록 `/notice`
- 테이블: 번호 · 구분(공지/이벤트/안내) · 제목 · 작성일 · 조회
- 상단 고정(중요) 공지는 번호 대신 라벨, 배경 구분
- 제목 검색, 페이지네이션
- 모바일은 카드형 리스트로 전환

### 5.2 상세 `/notice/[id]`
- 헤드(제목·구분·작성일·조회) + 본문 + 첨부파일 + 이전/다음 글

## 6. 인증 (AUTH)

### 6.1 화면
- **로그인**: 이메일·비밀번호, 로그인 유지, 소셜(카카오·네이버), 찾기 링크
- **회원가입 3단계**: ①약관 동의 ②정보 입력(이메일 중복확인·비밀번호·이름·휴대폰 인증) ③완료
- **마이페이지**: 주문내역(결제 도입 시) / 내가 쓴 후기 / 문의 내역 / 회원정보 수정 / 탈퇴

### 6.2 인증 정책
| 항목 | 정책 |
|---|---|
| 비밀번호 저장 | **BCrypt**. 평문·MD5·SHA 금지 |
| 비밀번호 규칙 | 8자 이상, 영문+숫자 조합, 흔한 비밀번호 차단 목록 |
| 로그인 시도 제한 | 5회 실패 → 10분 잠금 (IP + 계정 기준) |
| 토큰 | JWT를 **HttpOnly + Secure + SameSite** 쿠키에 저장. localStorage 금지 |
| 세션 | Access 30분 / Refresh 14일. 로그아웃 시 Refresh 무효화 |
| 소셜 로그인 | 카카오·네이버 (OAuth 2.0) |
| 만 14세 미만 | 가입 차단 또는 법정대리인 동의 (법률 확인 필요) |
| 탈퇴 | 즉시 처리. 개인정보 파기 + 법정 보존 대상은 별도 |

> 회원 정보는 민감하다. 개인정보처리방침 게시, 수집 동의, 보유기간 명시, 자동 파기가 **법적 의무**다. 법적 책임 주체는 사업자(라이즌푸드)임을 사전 합의한다.

## 7. 관리자

대표가 **개발자 없이** 상품·배너·공지를 관리할 수 있어야 한다. 전문용어를 쓰지 않고, 저장 전 미리보기를 제공하며, 삭제는 이중 확인한다.

### 7.1 대시보드
- 요약 지표: 오늘 방문 / 신규 회원 / 미답변 문의 / 노출 상품
- 최근 30일 추이 그래프
- 최근 문의, 재고 부족 알림
- **실제로 볼 것만 올린다. 쓰지 않는 차트는 넣지 않는다**

### 7.2 상품 관리
- **목록**: 순서(드래그 정렬) · 이미지 · 상품명 · 가격 · 재고 · 메인노출(★ 토글) · 노출 · 수정
- **등록/수정 폼**
  - 기본 정보: 상품명(한/영), 한 줄 설명, 가격·할인가, 용량·제공횟수·재고
  - 영양성분: 열량·탄수화물·단백질·지방·당류·나트륨 (항목 추가 가능)
  - 원재료·표시사항: 원재료명 및 함량, 원산지, 알레르기, 유통기한, 보관방법, 제조원
  - 상세 설명: 리치 텍스트 에디터 (저장 시 HTML 살균)
  - 이미지: 대표 + 추가 이미지, 드래그 정렬, **권장 크기 안내 문구 필수**
  - 구매 링크: 채널(네이버·쿠팡·자사몰) + URL, 복수 등록
  - 노출 설정: 사이트 노출 / 메인 노출 / 정렬 순서
  - 미리보기 → 저장

### 7.3 배너 관리
- **목록**: 순서 · 미리보기 · 노출 위치 · 제목·링크 · 노출 기간 · 상태
- **등록 폼**: 이미지(PC·모바일 각각), 제목(관리용), 연결 링크, 노출 위치, 노출 기간, 상시 노출, 새 창 열기, **대체 텍스트(접근성 필수)**

> **PC·모바일 이미지를 각각 받는다.** 하나로 쓰면 어느 한쪽이 반드시 깨진다. 노출 기간이 지나면 자동으로 내려간다.

### 7.4 그 외
| 화면 | 기능 |
|---|---|
| 공지사항 | 등록·수정·삭제, 구분, 상단 고정, 발행일 예약 |
| 회원 관리 | 목록·검색, 가입일, 상태(정상/휴면/탈퇴). **비밀번호 조회 불가** |
| 문의함 | 목록, 상태 관리, 답변 작성, CSV 내보내기 |
| 사이트 설정 | 기본 정보, SNS 링크, 푸터 사업자정보, 메인 섹션 노출 on/off |

## 8. 데이터 모델

> 지금은 제품이 하나지만 **처음부터 다제품 구조로 만든다.** 나중에 맛·용량이 추가될 때 데이터 모델부터 다시 짜야 하면 비용이 크다.

```sql
-- 상품
product(id, slug, name_ko, name_en, subtitle, description_html,
        price, discount_price, weight_g, servings, stock,
        thumbnail_key, is_featured, sort_order, visible, created_at)

product_image(id, product_id, image_key, type[MAIN|DETAIL|LIFESTYLE], sort_order)

nutrition(id, product_id, serving_size_g,
          kcal, carb_g, protein_g, fat_g, sugar_g, sodium_mg, extra_json)

ingredient(id, product_id, name, percentage, origin, allergen, sort_order)

purchase_link(id, product_id, channel[NAVER|COUPANG|OWN|OTHER],
              url, label, sort_order, visible)

-- 배너
banner(id, title, image_pc_key, image_mobile_key, alt_text, link_url,
       position[MAIN_TOP|MAIN_MID|PRODUCT_TOP], open_new_tab,
       start_at, end_at, always_on, sort_order, visible)

-- 공지
notice(id, category[NOTICE|EVENT|INFO], title, body_html,
       is_pinned, view_count, published_at, visible, created_at)
notice_file(id, notice_id, file_key, original_name, size)

-- 회원
member(id, email, password_hash, name, phone_encrypted,
       provider[LOCAL|KAKAO|NAVER], provider_id,
       status[ACTIVE|DORMANT|WITHDRAWN],
       terms_agreed_at, marketing_agreed_at,
       last_login_at, failed_count, locked_until,
       created_at, withdrawn_at, purge_at)

refresh_token(id, member_id, token_hash, expires_at, revoked_at)

-- 후기 · 문의
review(id, product_id, member_id, rating, content, image_key,
       verified_purchase, visible, created_at)

inquiry(id, member_id, type[GENERAL|WHOLESALE|PARTNERSHIP],
        name, email, phone_encrypted, message, answer,
        status, consent_at, created_at, purge_at)

-- 관리자 · 설정
admin_user(id, username, password_hash, role, last_login_at,
           failed_count, locked_until)
admin_audit_log(id, admin_id, action, target_type, target_id,
                ip, user_agent, created_at)
site_setting(key, value)
```

> **확장 대비** — 결제를 도입하면 `order`, `order_item`, `payment`, `delivery` 테이블이 추가된다. 지금의 `product`·`member` 구조는 그대로 재사용된다.

## 9. ⚠️ 식품 표시·광고 규제 (반드시 준수)

크림오브라이스는 **일반 식품**이지 건강기능식품이 아니다. 효능·효과를 표현하면 식품표시광고법 위반이다.

| ❌ 금지 | ✅ 허용 |
|---|---|
| 근육 증가에 도움 | 운동 후 탄수화물 보충 |
| 다이어트 효과 / 체지방 감소 | 1회 45g, 150kcal |
| 소화가 잘 됩니다 | 곱게 도정한 형태 |
| 위장에 좋은 | 자극이 적은 담백한 맛 |
| 질병 예방·치료 | (절대 사용 불가) |

**필수 표시사항**: 제품명 · 식품유형 · 원재료명 및 함량 · 내용량 · 영양성분 · 유통기한 · 보관방법 · 제조원/판매원 및 소재지 · 알레르기 유발물질 · 소비자상담실 연락처

> **후기도 관리 대상이다.** 사용자가 쓴 글이라도 "이거 먹고 살 빠졌어요" 같은 효능 단정 표현은 노출 전 검토·편집한다. 체험단·협찬 후기는 광고 표시가 필수다.

## 10. 보안

| 영역 | 대응 |
|---|---|
| 시크릿 | `.env` + gitleaks 훅. DB 비밀번호·키 커밋 금지 |

| 인증 | BCrypt, 시도 제한, JWT HttpOnly 쿠키, Refresh 무효화 |
| **CMS 에디터** | **저장 시 HTML 살균** — 상품 설명·공지 본문. 허용 목록 방식. 저장형 XSS의 주요 경로 |
| **파일 업로드** | 확장자·MIME·시그니처 검증 + **이미지 재인코딩** + S3 서빙 (앱 서버에서 파일을 서빙하지 않는다) |
| 권한 | 모든 관리 API에 `@PreAuthorize`. 하나만 빠져도 구멍 |
| 개인정보 | 휴대폰 컬럼 암호화, 처리방침 게시, 동의 체크박스, 자동 파기 배치 |
| 운영 | 자동 백업 + 복구 테스트 1회, UptimeRobot, Billing Alert |

## 13. 확정 필요 사항

| # | 항목 | 비고 |
|---|---|---|
| **1** | **AUTH의 목적** | ①주문·결제 ②후기·문의 이력 ③등급·적립 중 무엇인가. **①이면 장바구니·주문·결제·배송이 추가되어 범위가 두 배** |
| **2** | **판매 방식** | 자사몰 직접 결제 / 외부 채널 링크 / 병행. 자사몰이면 PG 계약·통신판매업 신고 필요 |
| **3** | **제품 사진 자산** | 누끼 유무, 해상도. **조리 과정 촬영 가능 여부**가 히어로 품질을 좌우 |
| 4 | 제품 정보 | 정확한 영양성분표, 원재료명·함량·원산지, 제조원·판매원, 유통기한 |
| 5 | 가격·구성 | 용량 종류, 가격, 할인 정책 |
| 6 | 브랜드 자산 | 로고 벡터, 브랜드 컬러, 서체 선호 |
| 7 | 소셜 로그인 | 카카오·네이버 사용 여부 (앱 등록 필요) |
| 8 | 후기 정책 | 회원만 작성? 구매자만? 사진 첨부 허용? |
| 9 | 배너 위치 | 메인 상단·중단 외에 필요한 곳 |
| 10 | 운영 | 문의 알림 수신처, 도메인 보유 여부, 호스팅 비용 부담 |
